# RAG-пайплайн в Langflow: поиск по 161-ФЗ о национальной платёжной системе

Рабочий RAG-пайплайн: чанкинг с overlap → эмбеддинги → двухэтапный поиск (вектор + реранкинг) → фильтрация по метаданным → генерация ответа в Langflow → трейсинг в Langfuse. Langflow и Qdrant поднимаются одной командой через docker compose.

## Контекст

Я аналитик, который строит прикладные инструменты на базе LLM. С LangGraph уже работал (Voice2Action: FastAPI + LangGraph + YandexGPT + Whisper + RAG). Этот репозиторий закрывает пробел по Langflow и LLMOps.

## Данные

Открытые статьи Федерального закона 161-ФЗ «О национальной платёжной системе»: термины и определения, требования к правилам платёжной системы, защита информации. Домен близок к банковскому, а официальные тексты законов не защищены авторским правом (п. 6 ст. 1259 ГК РФ). Файлы с текстами в репозиторий не включены, как воспроизвести корпус из официальных источников описано в `data/SOURCES.md`.

## Архитектурные решения

**Эмбеддинги: BGE-M3.** Открытая мультиязычная модель (в том числе русский), работает локально, без внешнего облака. Код не привязан к одной модели: интерфейс в `ingestion/embedders.py` поддерживает и Qwen3-Embedding-0.6B, переключение одной переменной окружения `EMBEDDING_BACKEND`.

**Чанкинг с overlap.** `ingestion/chunk.py` режет текст по абзацам и пунктам статьи, не разрывая определение посередине. Размер чанка около 900 символов, каждый следующий чанк начинается с хвоста предыдущего (150 символов). На юридическом тексте это важно: пункт 18 статьи 3 (определение электронных денежных средств) состоит из одного длинного предложения с оговоркой в конце, и нарезка фиксированным размером разрезала бы его на середине смысла.

**Двухэтапный поиск.** Сначала top-100 кандидатов по косинусной близости (быстро и грубо), затем реранкер (кросс-энкодер BGE reranker) точнее оценивает пары «вопрос, документ» и оставляет 3-5 лучших.

**Фильтрация по метаданным до векторного поиска.** Каждый чанк хранит метаданные из frontmatter документа (закон, глава, статья, источник). `retrieval/search.py` фильтрует по ним прямо в запросе к Qdrant, а не после: не нужно считать расстояние до заведомо неподходящих статей.

**Langfuse.** Трейсинг цепочки (retrieval → prompt → LLM), версионирование промпта, метрики токенов, стоимости и латентности.

## Результаты: side-by-side с реранкингом и без

`eval/run_sidebyside.py` прогоняет 10 тестовых вопросов по корпусу дважды (с реранкингом и без) и считает accuracy@1: попал ли топ-1 результат в ожидаемую статью.

| Бэкенд | Accuracy@1 без реранкинга | С реранкингом |
|---|---|---|
| BGE-M3 + bge-reranker-v2-m3 (прогон 28.09.2026) | 90% (9/10) | 90% (9/10) |
| hash-bow (офлайн-бэкенд для разработки и CI) | 40% (4/10) | 50% (5/10) |

На BGE-M3 единственный промах (вопрос q3 «Кто такой оператор платёжной системы?», ожидалась статья 20, оба варианта вернули статью 3) одинаков с реранкингом и без. Полная таблица по вопросам лежит в `eval/results.json` после запуска. Сравнение воспроизводится тем же скриптом при смене `EMBEDDING_BACKEND` в `.env`.

## Что проверено

- Конвейер от чанкинга до eval отработан на BGE-M3 + bge-reranker-v2-m3 и на офлайн-бэкенде (`HashEmbedder`, `LexicalOverlapReranker`), который позволяет гонять тесты без интернета.
- `docker compose up -d` поднимает Langflow (UI на :7860, `/health` отвечает 200) и Qdrant (:6333, коллекция `rag_knowledge_base`). Проверено 05.10.2026.
- Langfuse Cloud принимает трейсы запросов из Langflow.

## Быстрый старт

```bash
git clone <этот репозиторий>
cd langflow-rag
cp .env.example .env          # заполните ключи LLM при необходимости
docker compose up -d          # Langflow (7860) и Qdrant (6333); Langfuse по умолчанию облачный

python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# Индексация корпуса (первый запуск с bge-m3 скачает ~2.2 ГБ весов)
python -m ingestion.build_index --backend bge-m3 --qdrant http://localhost:6333

# Проверка поиска из консоли
python -m retrieval.search "какие требования к защите информации" --backend bge-m3 --rerank-backend bge

# Side-by-side eval
python -m eval.run_sidebyside --backend bge-m3 --rerank-backend bge
```

Дальше сборка визуальной цепочки в Langflow UI: `docs/LANGFLOW_SETUP.md`.

## Структура

```
data/
  raw/            markdown-документы корпуса (frontmatter = метаданные)
  SOURCES.md      источники и как воспроизвести корпус
ingestion/
  chunk.py        чанкинг с overlap
  embedders.py    BGE-M3 / Qwen3-Embedding / офлайн hash-эмбеддер
  build_index.py  сборка индекса в Qdrant
retrieval/
  search.py       двухэтапный поиск + фильтрация по метаданным
  rerankers.py    BGE reranker (кросс-энкодер) / офлайн lexical-реранкер
eval/
  questions.json      10 тестовых вопросов по корпусу
  run_sidebyside.py   сравнение с реранкингом и без
docs/
  LANGFLOW_SETUP.md   пошаговая сборка флоу в Langflow UI
docker-compose.yml    Langflow + Qdrant (Langfuse: облако или отдельно)
```

**Задача:** собрать не ноутбук с демо, а систему, которая поднимается через docker compose и воспроизводится одной командой.
