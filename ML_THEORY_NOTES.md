## Часть 1. Классификация — как модели предсказывают класс

### 1.1. Что реально выдаёт модель на выходе

Ни одна классификационная модель не выдаёт класс "напрямую" — она выдаёт **число (вероятность или "сырой балл")**, а класс получается сравнением этого числа с порогом.

- **LogReg**: линейная комбинация признаков `z = w1x1 + ... + b` → сигмоида `σ(z) = 1/(1+e^-z)` → вероятность класса 1 (число от 0 до 1). Класс = сравнение вероятности с порогом (по умолчанию 0.5).
- **Random Forest**: доля деревьев, проголосовавших за класс 1 (например, 730 из 1000 деревьев → 0.73).
- **Бустинг (XGBoost/CatBoost/AdaBoost)**: сумма вкладов всех деревьев ансамбля (сырой балл, "логит") → пропускается через ту же сигмоиду → вероятность.

**Логит** — сырое число до сигмоиды/softmax (может быть любым — большим, маленьким, отрицательным). Softmax/сигмоида — функция, сжимающая это число в диапазон [0,1] (softmax — для нескольких классов, сумма которых даёт 1; сигмоида — для бинарной задачи).

**Универсальный вывод для собеса:** *"Любая модель классификации на выходе даёт вероятность (или величину, интерпретируемую как вероятность), а не готовый класс. Класс — отдельный шаг: сравнение с порогом, который я выбираю осознанно под задачу, а не беру дефолтные 0.5."*

### 1.2. Классификация vs регрессия

- **Классификация** — таргет категориальный (дискретный, конечное число классов): дефолт/не дефолт, фрод/не фрод, тип корреспонденции.
- **Регрессия** — таргет непрерывный (число из большого/бесконечного диапазона): цена, сумма кредита, время обработки в часах.

LogReg, kNN, Random Forest, бустинг умеют работать в обоих режимах — меняется только финальный слой/функция потерь (сигмоида + LogLoss для классификации, линейный выход + MSE для регрессии).

### 1.3. Классификация vs кластеризация — как выбирать подход

**Главный вопрос при выборе подхода:** "Есть ли у меня историческая метка (label) того, что я хочу предсказывать?"

- **Есть метка, хочу предсказывать её на новых объектах** → классификация/регрессия (supervised). Модель целенаправленно учится отличать классы по явному примеру "вот правильный ответ".
- **Метки нет, хочу понять структуру данных** → кластеризация (unsupervised). Модель сама ищет похожие группы объектов, без подсказки, что "правильно".

**Мой кейс (credit-risk-scoring):** сначала попробовал кластеризацию (K-Means, Agglomerative) — гипотеза была "а вдруг заёмщики естественно делятся на группы риска даже без явного флага дефолта". Не сработало: ARI/AMI ≈ 0 — кластеры оказались никак не связаны с реальным дефолтом (естественная структура данных ≠ структура риска). Раз оказалось, что есть историческая разметка (флаг дефолта) — логично было перейти к классификации: явно обучать модель отличать дефолтных от недефолтных по известному примеру, а не надеяться, что она угадает сама. LogReg на классификации дал ROC-AUC 0.865.

**Инструменты по веткам:**
- Supervised (классификация/регрессия): LogReg, kNN, Random Forest, бустинг (XGBoost/CatBoost/LightGBM/AdaBoost) — все универсальные.
- Unsupervised (кластеризация): K-Means, Agglomerative, DBSCAN — специализированные, не умеют классификацию, у них нет механизма "учиться на правильном ответе".

## Часть 2. Метрики качества классификации

### 2.1. Precision и Recall

Из матрицы ошибок (TP, FP, FN, TN):

- **Precision** = TP / (TP + FP) — "из тех, кого назвал позитивным, сколько реально позитивных". Про доверие к положительному предсказанию.
- **Recall** = TP / (TP + FN) — "из всех реально позитивных, скольких поймал". Про полноту охвата.

Мнемоника: Precision — про чистоту находок (мало ложных срабатываний), Recall — "вспомнить всё", про то, что ничего не пропущено. Между ними всегда trade-off — двигаешь порог, теряешь в одном, выигрываешь в другом.

### 2.2. ROC-AUC vs PR-AUC — в чём разница и когда что

**ROC-кривая:** ось X — FPR (False Positive Rate) = FP/(FP+TN), ось Y — TPR (Recall) = TP/(TP+FN).
**PR-кривая:** ось X — Recall, ось Y — Precision.

**Ключевое отличие: TN участвует в ROC (через FPR), но нигде не участвует в PR.**

При сильном дисбалансе (фрод, дефолт — позитивного класса доли процента) TN — гигантское число почти всегда. FPR = FP/(FP+TN) — даже заметное количество FP тонет в огромном TN, FPR остаётся крошечным, ROC-кривая выглядит красиво независимо от реальной точности модели. Precision считается только через TP и FP — если модель заваливает ложными срабатываниями, Precision это сразу покажет, ROC-AUC — не обязательно.

**Формула для собеса:** *"ROC-AUC отвечает на вопрос, насколько хорошо модель отличает класс 1 от класса 0 в целом, включая огромное большинство. PR-AUC отвечает на вопрос, насколько можно доверять сигналу модели о позитивном классе и какую его долю она ловит — фокус только на редком классе. При сильном дисбалансе ROC-AUC может врать (оставаться стабильно высоким), PR-AUC честнее показывает реальную картину."*

### 2.3. Инвариантность ROC-AUC к монотонным преобразованиям

ROC-AUC = вероятность того, что случайно выбранный позитивный объект получит от модели более высокую вероятность, чем случайно выбранный негативный — это чисто про **порядок пар (ранжирование)**, не про абсолютные значения.

Если умножить все предсказания на константу, прибавить константу, применить любое **строго монотонное** преобразование (сохраняющее порядок) — ROC-AUC не изменится, потому что относительный порядок объектов не меняется.

**Вывод:** ROC-AUC — метрика ранжирования, не метрика калибровки. Модель может иметь отличный ROC-AUC (правильно упорядочивает по риску), но абсолютно неоткалиброванные вероятности (говорит 0.9, когда реальная частота на таких объектах — 30%). Отсюда — калибровка нужна отдельно (см. часть 4).

## Часть 3. Дисбаланс классов

### 3.1. Что реально даёт балансировка (SMOTE/undersampling/class weights)

**Без балансировки:** при сильном дисбалансе (99.9% против 0.1%) модель находит самый простой путь минимизировать общую ошибку — почти всегда предсказывать класс большинства. Loss-функция одинаково штрафует за ошибку на любом объекте, а раз позитивных примеров мало — их вклад в общий loss микроскопический, модели невыгодно "напрягаться" ради них.

**Что делает балансировка:** заставляет модель не игнорировать редкий класс.
- **Class weights** — ошибка на позитивном примере штрафуется сильнее (пропорционально дисбалансу) — не искажает данные, самый безопасный способ.
- **SMOTE** — генерирует синтетические позитивные примеры интерполяцией между реальными соседями — риск нереалистичных точек, особенно с категориальными признаками, снижает объяснимость перед регулятором.
- **Undersampling** — выбрасывает часть объектов большинства класса — опасен при экстремальном дисбалансе (в fraud-detection-balancing обрушил F1 с 0.859 до 0.114).

**Ключевой тезис (из fraud-detection-balancing):** балансировка — это калибровка рабочей точки классификатора (сдвигает, какую долю позитивного класса модель ловит), а НЕ улучшение самой модели. Экспериментально: ROC-AUC почти не меняется от SMOTE, а Recall скачет с 0.01 до 0.74 — внутренняя ранжирующая способность модели одна и та же, просто сдвигается порог отсечения.

**Качество признаков — жёсткий потолок**, который балансировка не пробивает. Сколько ни балансируй — если фичи слабые, выше определённого уровня метрика не поднимется.

**Практический вывод:** предпочитать class weights (или аккуратный undersampling только при умеренном дисбалансе), оценивать через PR-AUC, порог подбирать отдельно под бизнес-метрику, главный рычаг качества — feature engineering, не способ балансировки.

### 3.2. Стратифицированная кросс-валидация

При дисбалансе обычное случайное разбиение на фолды рискованно — можно случайно получить фолд без единого позитивного примера. Стратификация сохраняет пропорцию классов в каждом фолде.

## Часть 4. Cost-sensitive learning

### 4.1. Матрица затрат

В бинарной классификации 4 исхода: TP, TN, FP, FN. Для каждого можно посчитать стоимость `C(i,j)`, где i — прогноз, j — факт.

- `C(0,1)` (стоимость FN) — обычно наибольшая: одобрили мошенническую/дефолтную операцию.
- `C(0,0)` (стоимость TN) — близка к нулю.
- `C(1,0)` и `C(1,1)` — варьируются: колл-центр, потеря клиента, репутационные потери.

**Затраты на уровне класса** (грубо, один C_FN и один C_FP на весь класс) vs **затраты на уровне объекта** (точнее — цена своя для каждой конкретной заявки, например пропорционально сумме кредита). Затраты на уровне объекта реалистичнее, потому что мошенническая/дефолтная заявка на разные суммы имеет разную цену ошибки.

**Как получить цену объекта практически:** не нужна ручная разметка всего датасета — это формула поверх уже существующих бизнес-полей: `cost_FN = сумма_кредита`, `cost_FP = сумма_кредита × ставка × доля_упущенной_маржи`. Экспертная оценка нужна только для косвенных затрат (репутационные потери и т.п.), и то один раз, для калибровки формулы, а не построчно.

### 4.2. Порог классификации через денежную метрику

Модель отдаёт вероятность, порог не обязан быть 0.5.

```
Total_Loss(threshold) = FN_count(threshold) × cost_FN + FP_count(threshold) × cost_FP
```

Перебираешь пороги, для каждого считаешь TP/FP/FN/TN на тесте, считаешь Total_Loss, выбираешь порог, который её минимизирует — вместо максимизации F1/Accuracy.

### 4.3. AdaBoost и его cost-sensitive вариации

**AdaBoost (Adaptive Boosting)** — ансамбль слабых классификаторов (обычно деревья глубины 1 — "пни"), обучаемых последовательно. Каждый следующий классификатор фокусируется на объектах, которые предыдущие классифицировали неправильно, — их вес увеличивается для следующей итерации. Финальный результат — взвешенное голосование всех деревьев.

Уникальность AdaBoost: работает через **перевзвешивание объектов** между итерациями (не градиентный спуск в строгом смысле), использует **экспоненциальную функцию потерь** `L = e^(-y·f(x))` — резко растёт для сильно ошибочных предсказаний, отсюда чувствительность AdaBoost к шуму/выбросам.

**Cost-sensitive вариации** — встраивают стоимость `C_i` объекта прямо в формулу обновления весов:
- **AdaC1** — стоимость внутри экспоненты формулы обновления веса.
- **AdaC2** — стоимость снаружи, множителем за экспонентой.
- **AdaC3** — стоимость и внутри, и снаружи одновременно (самый агрессивный вариант, обычно даёт наибольший эффект).
- **AdaMEC** — добавляет правило минимальной ожидаемой стоимости (оптимизация порога с учётом затрат), обычно с калибровкой.
- **CGAda** — начальные веса объектов = их затраты.
- **CSDT** — cost-sensitive деревья решений, затраты на уровне объекта, а не класса.
- **CSRP (Cost-Sensitive Random Patches)** — cost-sensitive бэггинг: ансамбль обучается на случайных подмножествах объектов И признаков одновременно ("patches" — вырезки в двух измерениях), с учётом стоимости.

**Риски cost-sensitive подхода (важно проговорить, не только плюсы):**
1. **Overfitting на дорогие объекты** — модель чрезмерно подстраивается под шум дорогих объектов. Типичный симптом: модель (например, CSRP) показывает высокий Savings, но с явным разрывом качества между train и test — признак переобучения; правильная реакция — исключить такую модель из финальных рекомендаций, не пытаясь её "починить" искусственно.
2. **Просадка на массовом классе** — рост ошибок на дешёвых/частых объектах ради точности на дорогих редких.
3. **Зависимость от качества оценки затрат** — если матрица `C(i,j)` неточная (часто экспертная прикидка), модель красиво минимизирует неправильно заданную метрику (GIGO).
4. **Риск нестабильности во времени** — агрессивная фокусировка на редких/дорогих объектах может сделать модель более чувствительной к сдвигу данных (data drift).

### 4.4. Применимо ли сейчас (2026), и почему индустрия сместилась на градиентный бустинг

AdaBoost/AdaC1-3 в чистом виде — не мейнстрим сегодня. Идея жива, инструмент сменился на XGBoost/CatBoost/LightGBM через:
- **sample weights** — прямой аналог AdaC-подхода: передаёшь вес = стоимость ошибки для каждого объекта при обучении.
- **custom loss function** — пишешь свою функцию потерь, явно штрафующую по денежной матрице.

**Почему сместился фокус:**
1. AdaBoost жёстко привязан к экспоненциальной функции потерь — градиентный бустинг работает с любой дифференцируемой функцией потерь (общая рамка, а не частный случай).
2. Более глубокие деревья (3-10 уровней вместо пней) улавливают взаимодействия признаков за одну итерацию.
3. Инженерная зрелость — годы оптимизации под скорость, параллелизацию, обработку пропусков и категориальных признаков (особенно CatBoost).
4. Встроенная регуляризация против переобучения — то, чего у AdaBoost нет, а это прямая защита от риска №1 выше.

**Разница "с градиентным спуском / без":** AdaBoost меняет веса объектов эвристически (не градиентный спуск в строгом смысле). Градиентный бустинг — каждое следующее дерево обучается предсказывать **градиент функции потерь** (насколько и куда скорректировать текущее предсказание ансамбля) — это буквально шаг в направлении антиградиента, отсюда и название.

## Часть 5. Виды бустинга и других табличных алгоритмов

### 5.1. Бустинг — общая идея

Строит **сильную** модель из множества **слабых** (обычно неглубокие деревья), обучаемых **последовательно** — каждое следующее знает про ошибки предыдущих и целенаправленно их исправляет. Отличие от **бэггинга** (Random Forest) — там деревья строятся независимо и параллельно, результат усредняется/голосуется.

### 5.2. Конкретные реализации

- **AdaBoost** — адаптивное перевзвешивание, экспоненциальная потеря, деревья-пни.
- **Gradient Boosting (GBM)** — общий принцип: следующее дерево учится на градиенте функции потерь.
- **XGBoost** — GBM + сильная регуляризация + оптимизация скорости.
- **LightGBM** — GBM + leaf-wise построение дерева (растёт вглубь там, где выгоднее) + гистограммное разбиение — быстрее на больших данных.
- **CatBoost** — GBM + нативная обработка категориальных признаков (без ручного target/one-hot encoding) + ordered boosting (снижает утечку данных).

**Категориальные признаки → всегда ли лучше CatBoost:** нет железного правила. CatBoost даёт удобство (меньше препроцессинга) и часто хорошее качество "из коробки", но XGBoost/LightGBM с грамотным ручным target encoding часто показывают сопоставимый или лучший результат. Решение — всегда через сравнение на кросс-валидации, не по умолчанию.

### 5.3. Другие алгоритмы для табличных данных

- **Random Forest (бэггинг)** — много независимых деревьев на bootstrap-выборках (случайная выборка с возвращением) + случайное подмножество признаков на каждом разбиении. Снижает дисперсию.
- **LogReg** — линейная комбинация + сигмоида, интерпретируема, быстро обучается, плохо ловит нелинейности без ручного FE.
- **LinReg** — для непрерывного таргета, минимизирует MSE.
- **kNN** — предсказание по k ближайшим соседям (голосование для классификации, среднее для регрессии). Не требует обучения в привычном смысле, медленный на больших данных, чувствителен к масштабу признаков (нужна нормализация).
- **SVM** — ищет разделяющую гиперплоскость с максимальным зазором.
- **Naive Bayes** — вероятностный, наивно предполагает независимость признаков, быстрый baseline.
- **Decision Tree** — единичное дерево, легко переобучается само по себе, но интерпретируемо.

## Часть 6. Калибровка вероятностей

### 6.1. Зачем нужна

Модель выдаёт число 0-1, похожее на вероятность, но часто им не является: модель может говорить "0.9" на группе объектов, где реально позитивных только 60%. Калибровка — исправление этого системного перекоса, чтобы число реально соответствовало частоте события.

**Зачем практически:** для расчёта денежных потерь (Total_Loss из части 4.2) нужны честные вероятности — если модель врёт про вероятности, расчёт ожидаемых потерь тоже будет неверным, даже при правильно подобранном пороге.

### 6.2. Логиты и softmax/сигмоида

**Логит** — сырое число на выходе модели до финального преобразования (может быть любым). **Softmax** (для нескольких классов, сумма выходов = 1) или **сигмоида** (для бинарной задачи) сжимает логит в диапазон [0,1]. Аналогия: логит — сырой балл (-1000..+1000), softmax/сигмоида — перевод в проценты. Калибровка — донастройка ПОВЕРХ уже посчитанной сигмоидой вероятности, если даже после неё числа всё ещё не отражают реальную частоту.

### 6.3. Методы калибровки

- **Калибровка Платта** — обучает логрег с одним входным признаком (сырое предсказание исходной модели) и таргетом (реальный класс): `откалиброванная_вероятность = σ(A × сырое_предсказание + B)`, A и B подбираются на отдельной выборке (не той, на которой обучалась основная модель). Хорошо, когда искажение похоже на сигмоидную форму (типично для SVM, AdaBoost).
- **Изотоническая регрессия** — непараметрическая: ищет любую монотонно возрастающую ступенчатую функцию, преобразующую сырые предсказания в реальные частоты. Гибче Платта, но требует больше данных, иначе переобучается. Использует PAV-алгоритм.
- **Beta calibration** — более гибкая параметрическая альтернатива Платту, для несимметричных искажений.
- **Temperature scaling** — один параметр (температура) масштабирует логиты перед softmax, популярен для нейросетей.
- **Histogram binning** — делит предсказания на бины, для каждого бина считает реальную частоту позитивного класса — просто, но грубо.

**Проверка качества калибровки:** reliability diagram (calibration curve) — разбить предсказания на бины, для каждого посчитать реальную долю позитивных, сравнить с заявленной вероятностью бина.

**Эмпирический вывод из практики:** калибровка значительно улучшает Savings (денежную метрику) для cost-sensitive моделей — подтверждает необходимость калибровки при использовании cost-sensitive подходов.

## Часть 7. Стабильность модели во времени

### 7.1. PSI (Population Stability Index)

Измеряет, насколько распределение предсказаний модели в текущем периоде отличается от распределения в "эталонном" (обучающем) периоде.

**Пороговые значения:**
- PSI < 0.1 — незначительное изменение, действий не требуется.
- 0.1 ≤ PSI ≤ 0.25 — есть изменения, стоит уделить внимание другим метрикам.
- PSI > 0.25 — значительные изменения, нужно перекалибровывать/пересматривать модель.

### 7.2. Почему модель может быть нестабильной

Типичная ситуация: обычный AdaBoost с калибровкой Платта показывает **лучший** результат по Savings, но **нестабильный** PSI по кварталам — правильное решение — предпочесть менее выигрышную, но более стабильную модель (например, AdaC3 + изотоническая калибровка) вместо гнаться за лучшей метрикой на одном срезе времени.

**Механизм:** модель, оптимизирующаяся под общую точность (без фокуса на дорогих объектах), может случайно "поймать удачную волну" в конкретном периоде (например, в этом квартале было много легко распознаваемых случаев) — высокий результат оказывается скорее случайностью, чем устойчивым поведением. Cost-sensitive модель, фокусирующаяся на объектах с высокой ценой ошибки с самого начала обучения, обычно более консистентна во времени, потому что "дорогие" паттерны обычно устойчивее, чем общая точность на всей выборке.

**Как объяснить бизнесу одной фразой:** *"Модель может показать отличный результат один раз случайно — как выигрышный лотерейный билет. PSI показывает, действительно ли модель стабильно хороша, или нам просто повезло с периодом тестирования."*

## Часть 8. Прокси-таргет

### 8.1. Что это и зачем

Когда нужная целевая переменная либо редкая, либо дорого/долго собирается (мошенничество — требует ручного расследования и подтверждения от клиента), используют **другую переменную, сильно коррелирующую с ней и собираемую автоматически**.

**Типичный пример из антифрода:** реальный флаг мошенничества собирать дорого, зато ранний дефолт (просрочка 3-30 дней) собирается автоматически из системы. Логика связи: если мошенник оформил кредит на чужие документы — реальный владелец не знает о кредите и не платит; или клиент, узнав о мошеннически оформленном кредите, сознательно перестаёт платить до разбирательства. В обоих случаях — платежи не идут в первые месяцы.

### 8.2. Как проверить, что прокси действительно похож на целевую переменную

Обучить две отдельные модели (одна на реальном таргете, другая на прокси), сравнить их предсказания на одних и тех же объектах:
1. **Scatter plot**: по X — предсказание модели А, по Y — предсказание модели Б, для одних и тех же объектов. Если предсказания не связаны — облако хаотично разбросано. Диагональная концентрация — визуальный признак положительной корреляции.
2. **Численно**: коэффициент корреляции (Спирмен обычно безопаснее по умолчанию — ловит любую монотонную связь, не только линейную, устойчив к выбросам; Пирсон — только для строго линейной связи, чувствителен к выбросам) между предсказаниями двух моделей + p-value (значимость).

```python
from scipy.stats import spearmanr
corr, p_value = spearmanr(model_a_scores, model_b_scores)
```

### 8.3. Как выбрать Спирмен или Пирсон

- **Пирсон** — линейная связь, чувствителен к выбросам, требует, чтобы зависимость была именно прямой линией.
- **Спирмен** — монотонная связь (необязательно линейная), считает по рангам, устойчив к выбросам, ловит и нелинейные (но монотонные) зависимости.
- **По умолчанию бери Спирмен** — безопаснее, почти никогда не хуже Пирсона для типовых задач. Пирсон — только если есть явные основания полагать линейность и отсутствие сильных выбросов.

### 8.4. Ключевой риск прокси-таргета — и как его снижать

Прокси — всегда приближение. Модель на дефолте будет ловить не только мошенничество, но и просто "плохих плательщиков без злого умысла" (потеря работы, забывчивость) — шум.

**Способы снизить шум:**
1. **Multi-signal labeling** — комбинировать несколько независимых прокси-сигналов вместо одного (ранний дефолт И поведенческие аномалии И странности в заявке).
2. **Ручная разметка подвыборки (active learning)** — проверить вручную небольшую выборку через звонок/сверку документов, дообучить на этой более чистой подвыборке (semi-supervised: большая грязная + маленькая чистая).
3. **Дополнительные признаки-фильтры** — скорость наступления дефолта (мошенник обычно не платит резко и полностью с первого платежа), сумма кредита, поведенческие паттерны заявки.
4. **Down-weighting шумных объектов** — вместо жёсткой метки 0/1, вес уверенности (soft label).
5. **Постепенное накопление реальных меток** параллельно с использованием прокси, периодическая перепроверка модели против них.

## Часть 9. Статистические тесты (из tbank-reviews-analysis)

### 9.1. Спирмен — корреляция

Монотонная связь между двумя числовыми/ранговыми переменными. ρ от -1 до +1 + p-value. Устойчив к ненормальности и выбросам (в отличие от Пирсона). Пример: скорость обработки ↔ недовольство (ρ = −0.47).

### 9.2. ANOVA — дисперсионный анализ

Отличаются ли средние значения количественной переменной между 3+ группами (для 2 групп — t-test). F-статистика + p-value. Говорит только "есть разница где-то", не "между какими группами" (для этого — post-hoc тесты, например Тьюки).

### 9.3. χ² (хи-квадрат)

Связаны ли между собой две категориальные переменные. Строится таблица сопряжённости, сравниваются наблюдаемые частоты с ожидаемыми при полной независимости. Статистика χ² + p-value.

### 9.4. Как выбрать тест

| Тип данных | Тест |
|---|---|
| Числовая × числовая | Спирмен |
| Числовая × категориальная (3+ группы) | ANOVA |
| Числовая × категориальная (2 группы, неравные дисперсии) | t-test Уэлча |
| Категориальная × категориальная | χ² |

## Часть 10. Кросс-валидация vs бутстрап

### 10.1. Зачем вообще сравнивать модели через CV, а не на одном сплите

Один train/test сплит может оказаться случайно удачным/неудачным. CV даёт усреднённую оценку по нескольким разбиениям + показывает стабильность (разброс между фолдами), а не только среднее качество.

### 10.2. Кросс-валидация — механика

Данные делятся на непересекающиеся части (фолды), без повторов. Каждый объект попадает в тест ровно один раз за весь цикл. Используется в первую очередь для честной оценки/сравнения моделей. Применима к ЛЮБОЙ ML-модели, не только к бустингу (LogReg, kNN, RF — тоже).

**Стратифицированная CV** — сохраняет пропорцию классов в каждом фолде (критично при дисбалансе).

### 10.3. Бутстрап — механика

Сэмплирование **со случайным возвращением**: объект может попасть несколько раз в одну выборку, некоторые не попадут вообще (out-of-bag, OOB).

**Применение:**
1. Как строительный механизм **внутри алгоритма** — bagging = "bootstrap aggregating", основа Random Forest: каждое дерево на своей bootstrap-выборке, OOB-объекты служат естественным тестом для этого дерева.
2. Как отдельный статистический метод — оценка неопределённости/доверительных интервалов метрики: многократно пересэмплировать данные, каждый раз считать метрику, смотреть на разброс полученных значений.

### 10.4. Разница одной фразой

CV делит без повторов, каждый объект тестируется один раз — для честной оценки/сравнения моделей. Бутстрап сэмплирует с повторами и пропусками — строительный блок бэггинга и инструмент оценки неопределённости метрики.
